# Предложение для будущей системы достижений

Это исследование данных, а не утверждённые правила начисления. Текущая задача не создаёт баллы, рейтинг или достижения.

## Доступные данные

- `task_events` хранит `APPROVE`/`ADMIN_APPROVE` с временем, исполнителем, действовавшими на приёмке исходной и текущей датами срока. `Task.completed_at` и `Task.status` позволяют сверить завершение.
- `REJECT` фиксирует отказ исполнителя и причину; `CREATED`/`UPDATED` содержат назначение и переназначение. Одно текущее состояние задачи не заменяет историю предложений назначения.
- `QA_REVIEW_DONE` и `REQUEST_REWORK` различают проверку QA и окончательную приёмку автором.

## Формула для согласования

- Для «Пунктуального» предлагается считать `on_time / completed_assigned` только по принятым задачам, где пользователь был основным исполнителем на момент приёмки. Время сравнивается с концом обязательной календарной даты в `Asia/Tashkent`. Минимальное число задач и порог доли должен утвердить владелец.
- Для «Опаздуна» предлагается аналогичная доля `late / completed_assigned`, с отдельным минимумом наблюдений: один поздний результат достижение не даёт.
- Для «Всегда занят» предлагается `REJECT / offers`, где предложение назначения строится по событиям; повторные события одной попытки не должны увеличивать знаменатель. Минимум предложений и порог отказов требуют решения.
- Как *черновой вариант* баллов: `+10` за принятую в срок задачу, `0` за позднюю; отменённые и незавершённые задачи не оцениваются. Штрафы, бонусы и окончательная шкала не утверждены.

## Решения владельца до реализации

Нужны пороги достижений, минимальные объёмы, период расчёта, исходный или изменённый срок для оценки, правила при переназначении и повторной доработке, баллы за отказ и политика исправления ошибочно начисленных баллов. Названия и пороги должны быть настраиваемы.

Для защиты от повторного начисления понадобится ledger с уникальным ключом на `rule_version + task_event_id + user_id`; его схему и алгоритм пересчёта следует проектировать после утверждения формулы. Исторические сравнения должны использовать события, а не выводиться из текущего статуса.
